---

- **상태**: 채택
- **날짜**: 2026-09-25

## 맥락

Electron만으로는 다른 앱의 창을 찾거나 옮길 수 없습니다. 필요한 것은 macOS Accessibility(AXUIElement), CGWindowList, 비공개 CGS 호출, 전역 마우스 감시, 키 입력 합성입니다. 선택지는 셋이었습니다.

| 선택지                          | 장점                                                          | 단점                                                                                           |
| ------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| N-API 네이티브 애드온 (Obj-C++) | 같은 프로세스, 호출 지연 없음                                 | Electron 버전마다 재빌드, 응답 없는 앱의 AX 호출이 메인 스레드를 막음, 크래시가 앱 전체로 번짐 |
| osascript / JXA                 | 코드가 적음                                                   | 호출당 100ms 이상, 창 ID·Space 정보 없음, 추가 자동화 권한 필요                                |
| **Swift 헬퍼 프로세스**         | Swift로 macOS API를 자연스럽게 사용, 크래시 격리, 단독 테스트 | 바이너리를 함께 서명·배포해야 함, 프로세스 간 통신                                             |

## 결정

`native/MagWinHelper`에 Swift 실행 파일을 두고, Electron 메인이 자식 프로세스로 띄워 stdin/stdout **JSON Lines**로 통신합니다([헬퍼 프로토콜](../helper-protocol.md)).

- 헬퍼 내부도 순수 로직(`HelperCore`, Swift Testing으로 검증)과 OS 어댑터(`HelperPlatform`)로 나눕니다.
- 메인 쪽에서는 `HelperClient`가 요청·응답을 짝짓고 zod로 결과를 검증하며, 각 기능은 포트 인터페이스(`WindowMover` 등)를 구현한 얇은 어댑터로만 헬퍼를 씁니다.
- 헬퍼가 죽으면 `HelperProcess`가 지연 시간을 늘리며 다섯 번까지 다시 띄웁니다.

## 결과

- 권한(TCC)은 헬퍼를 띄운 **책임 프로세스**에 붙습니다. 패키징된 앱에서는 magWin.app, 개발 모드에서는 `pnpm dev`를 실행한 터미널 앱입니다.
- 통신 지연은 1ms 미만이라 체감 차이가 없습니다. 가장자리 판정은 헬퍼 안에서 끝나고 결과 이벤트만 넘어옵니다.
- 배포 시 헬퍼 바이너리도 앱과 같은 인증서로 서명해야 합니다([배포](../../development/release.md)).
